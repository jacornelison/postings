Fixing El wrapping near Zenith

2025 Mmm dd — J. Cornelison

This is annoying for studies where differentiating between two spots with the same topocentric elevation, but different mount elevations (e.g. El=80° and El=100°). I think I've come up with a fix for current studies using our beam mapping pointing models, but there exists a real bug in our current CMB pointing code that we should probably fix. Further, only a few people are familiar with the bm functions, so I'd like to propose replacing our CMB pointing code with the beam mapping models.

The Problem

invpointing_model

[see ] The main CMB analysis pointing model that converts mount coordinates to topocentric AZ/El/PA. All of the calculations are done algebraically which, while efficient, require some cludges to make work due to singularities and degeneracies.

This function has a cludge at the end that unwraps the elevation, but it's broken in two ways:

  1. It unwraps EL according to the input mount coords, which is only approximate. You can see in Fig 1.1 that the wrap occurs well before it should for large tilts.
  2. It only unwraps EL while keeping AZ the same. This means that the pointing is actually incorrect. Further, it's not actually straightforward to just add 180° to AZ to rectify it due to all of the tilts.

beam_map_pointing_model

[see ] Because the beam map pointing model is all done in vector space, calculating the final output coordinates after all of the rotations are done, we only really have the issue of breaking degeneracy between two points of the same elevation.
